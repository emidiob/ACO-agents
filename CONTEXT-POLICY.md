# ACO context policy

Public expertise is stable; private identity/strategy/history is mutable. No private context is embedded in agent methods.

**NONE/BLIND:** no private fetch. **LIGHT:** relevant basics. **FULL:** all relevant approved material, never indiscriminately all files. **BLIND-FIRST:** independent first stage, then a separately contextualized stage. Earlier chat content is not erased.

Resolve a task-local scope using stable entity IDs. Do not use a global current client. Preserve distinct organization, activity, client, brand, project and personal scopes. Provider permissions, not prompt text or folder names, determine actual access.

Canonical context, immutable work events, approved decisions, open loops and handoffs are distinct. Context promotion needs evidence/approval and a fresh base revision. A failed/absent remote write must remain pending or not saved, never silently “remembered”.
