# Web and UI quality contract

For web marketing pages: distinct subject, real content/visual assets, one editorial idea translated into page composition, real responsive page at 3 viewports, rendered DOM and interaction checks, screenshot critique and correction loop. For UI/app screens: preserve workflows, actions, data, roles and error states; design hierarchy from primary user task rather than from hero-card aesthetic. Do not replace an established component library without a scoped decision. Existing ACO Webdesign's 62 rules and live rendering tools remain available and may be preferable to Taste's simple CLI heuristics.

**Evidence:** actual before/after screenshots; responsive, keyboard, loading/empty/error/selected, contrast and reduced-motion as applicable. A screen without a real browser cannot be certified visually reviewed.
