# Product Office Briefing Guide

Use this office when the work involves a website, app, software feature, internal tool, API, AI feature or technical platform.

## Minimal pattern

```text
Use the Product Office.
Load the relevant company, product, technical and project context.
Task: [what needs to be built, fixed, designed or decided]
Objective: [why this matters / what success looks like]
Deliverables: [what you want back]
Constraints: [budget, timing, stack, compliance, performance, accessibility, etc.]
```

## Examples

### Website

```text
Use the Agency Office and Product Office.
Load the client, brand, product and technical context.
We need to redesign and rebuild the client's website.
Agency Office owns brand, UX and visual direction.
Product Office owns architecture, implementation, QA and deployment.
First produce IA and page templates, then implementation plan, then build.
```

### Web app

```text
Use the Product Office.
Load the company, product and technical context.
Build a web application for uploading, organizing and annotating images.
Start with requirements and critical user flows.
Then define architecture, data model and implementation plan.
Prototype before full implementation.
```

### Bug diagnosis

```text
Use the Product Office.
Load the product and technical context.
Users are being logged out unexpectedly after OAuth sign-in.
Reproduce the bug, isolate probable causes, propose a fix and define regression tests.
```

### AI feature

```text
Use the Product Office.
Load the product, technical and project context.
We want an AI assistant inside the platform.
Define the user jobs, interaction model, model/tooling approach, evaluation plan and implementation architecture.
```

### Artist website

```text
Use the Artist Office and Product Office.
Load my artist context, plus product and technical context.
Artist Office owns the representation of the practice and editorial hierarchy.
Product Office owns architecture, implementation and deployment.
```
