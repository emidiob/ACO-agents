# Diagnose an actual result

Compare the supplied render with the source and the requested change. Inspect the problem interval, including the frames immediately before and after it. Separate prompt ambiguity, reference conflict, unsupported controls and model instability. Fix the smallest demonstrated cause; do not promise that a rerun will solve it.

| Observed problem | Check first | Targeted response |
|---|---|---|
| Action occurs in the wrong order | Event table and reference timestamps | Clarify the transition and bind the relevant anchor |
| Object floats or grip breaks | Support/contact frames and occlusion | Provide the inspected contact anchor and specify maintained support |
| Identity or wardrobe changes | Competing appearance references | Assign one source per attribute and repair inconsistent anchors |
| Head faces forward during a back view | Orientation of the anchor versus identity photo | Preserve body/head direction at that moment; do not force face visibility |
| Camera moves when it should hold | Conflicting framing/movement clauses | Remove the contradictory move and identify the stable reference |
| Unwanted cuts | Ambiguous shot boundaries or overloaded action | Identify continuous intervals; simplify or separate shots only if acceptable |
| Wrong number of people/objects | References containing irrelevant subjects | Limit each reference's role and specify the visible count at the event |
| Sound differs from the source | Provider audio handling | Use a verified audio control or propose retaining the source track in editing |
| Letters change | Whether exact text generation is supported | Keep exact typography as a separate editing task when precision is required |
| Local flicker or brief deformation | Exact extent of the defect | Propose a bounded edit or replacement interval, preserving required timing |

A repair may change synchronization or duration. Do not casually remove frames from a clip whose timing must match the source. For each proposed correction state the affected interval/property, the evidence and what should remain unchanged. Renders and editing actions require the user's corresponding authorization. Once supplied, inspect the new result before claiming improvement.

If a provider rejects an input, use its legitimate supported workflow or explain the limitation. Do not disguise the same blocked input or switch accounts to evade a restriction.
