# Learning from work without contaminating scopes

ACO may turn repeated, evidenced corrections into better local instructions, but it must not silently convert every conversation into global policy.

## Capture candidates, not automatic truths
A useful lesson has:
- a clear trigger;
- one concise behavior / rule;
- evidence such as a user correction, repeated failure resolution or stable approved preference;
- an explicit scope.

## Scope levels
- **Task / session:** useful now; do not persist unless needed for continuity.
- **Project / client:** specific to one active scope (for example a brand voice or delivery convention).
- **Organization / practice:** stable for that owner but not universal.
- **ACO-wide:** only for truly general operating behavior.

Prefer the narrowest valid scope. Never promote client-specific taste, confidential facts or one-off corrections into a global ACO skill.

## Promotion gate
A lesson can become a durable instruction only after review. Strong evidence includes repeated confirmation across tasks or an explicit human decision. Conflicting evidence blocks promotion until reconciled.

## Storage
Do not create a file per lesson. Put durable scoped preferences in the existing canonical ACO document or update the relevant ACO method during library development. Do not auto-import raw transcripts, private chain-of-thought, credentials or unreviewed tool logs.

## Retiring lessons
When a newer approved rule supersedes an older one, update the canonical instruction and preserve only the history needed to explain active decisions. Do not let stale preferences accumulate indefinitely.
