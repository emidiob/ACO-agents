# Code reference method

Use catalogues and educational repositories as references, not production dependencies by default.

1. Define the actual programming problem and runtime constraints.
2. Prefer language/platform standard capabilities before pulling snippets or packages.
3. Use examples to compare complexity, readability and edge cases.
4. Re-implement only what is appropriate for the codebase; preserve required attribution/license notices when copying protected material.
5. Add tests for the real inputs, error cases and performance requirements.
6. For API catalogues, verify the provider’s current official docs, auth, quotas, terms, data rights and status.
