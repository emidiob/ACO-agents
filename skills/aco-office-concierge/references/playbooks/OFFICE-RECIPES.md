# Six office recipes with compact memory

Recipes are on-demand instructions until a real scheduler is explicitly configured and its creation verified. Example times from the supplied screenshots (08:00 daily, Monday 09:00, Friday 17:00) are not installed schedules. Ask for timezone, DST behavior, authorized accounts/root, delivery channel and scope before scheduling. A missed run does not authorize duplicate sends.

## Daily To Do
Read only the authorized inbox scope and relevant project state. Identify messages requiring response, deadlines and blockers. Deduplicate by stable message/thread/task IDs. Update the existing board or the same ACO.md open-actions section; return one digest. Do not create a task file per email. Gmail/Calendar/Contacts capabilities must be inspected separately.

## Weekly Leads
Use an approved ideal-client profile and exclude existing/contacted/declined prospects. Find a small verified shortlist (three is an example, not a rule), audit relevant public sites and draft tailored messages. Store short lead rows in the commercial pipeline. A contacted prospect does not become a client or project. Do not send or create external drafts without applicable authorization; in-chat drafts are the fallback.

## Communications
Turn supplied/authorized call notes into a requested proposal/SOW/email. Verify commitments and names; ask about missing recipient/account/scope or material terms before action. Save a real requested deliverable when needed, but no new project tree for an unaccepted pitch. Email, WhatsApp, SMS and calls need distinct tools and exact approval; unknown outcome requires reconciliation, not blind retry.

## Filing
Inventory only approved local/remote roots. Separate primary deliverables from generated ACO notes. Show exact proposed moves/renames/duplicates before action. Byte equality or a folder named Rejected is not deletion permission. Use revision/hash checks, recoverable batches and explicit plan approval. No unbounded Downloads scans, source master deletion or changes to unrelated clients.

## Client onboarding
First verify accepted/active scope or import of a real client. Reuse existing client/project records. Put the kickoff checklist and timeline in the existing project ACO.md or existing board unless a separate deliverable is requested. Keep leads inline until promotion. Clarify deliverables, approvers, rights/payment and access—not ten empty folders.

## Weekly Ops
Review only authorized active projects, pipeline, inbox and board. Reconcile status, cost/schedule blockers and commitments. Update existing records; create no Friday-report archive by default. Deliver one roundup with decisions needed and next actions. Financial/HR/restricted data stays within its own boundary.

Notion is optional and is not an extra default source of truth. Reuse the user’s existing board; do not duplicate all memory into it. Agentic Inbox is an optional dedicated mailbox deployment, not a required Gmail replacement. Its reviewed README warns that a shared Access policy can expose all mailboxes to authorized users; separate storage is not per-client access control. Review that before any multi-client use.

Source pattern: user-supplied office automation screenshot, adapted into original ACO workflows. Optional implementation reference: [Cloudflare Agentic Inbox](https://github.com/cloudflare/agentic-inbox). No service or schedule is installed by this release.
