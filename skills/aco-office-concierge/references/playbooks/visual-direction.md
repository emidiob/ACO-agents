# Visual direction without a house-style monoculture

## Scope and early questions
Use for a brand-facing page or design system, not as a compulsory strategy workshop before every CSS fix. Inspect supplied brand assets, site, content and relevant private brief first. Clarify only the unresolved audience/task, locked brand choices and required delivery. A speculative route is allowed if labelled; do not fabricate client approval or research.

## Procedure
1. Write a compact design contract: visitor, job to complete, priority content, emotional register, accessibility constraints, existing assets and non-negotiables. Keep organizational facts separate from provisional visual decisions.
2. Identify page types and content weight before selecting components. A portfolio, publication, store and internal dashboard do not share one default landing-page structure.
3. When exploration is commissioned, develop two or three genuinely different systems, not colour swaps: different typographic hierarchy, density, image behaviour, grid rhythm and navigation. Explain the tradeoff in one paragraph each. For a locked route, skip alternative generation and execute.
4. Build a representative page or spread with realistic-length content. Define spacing rhythm, type roles, readable measure, responsive reflow and image crops. Record any missing font or asset licence; never distribute fonts from the host machine.
5. Specify interactions and states: keyboard focus, hover only as enhancement, loading, empty, error, long labels and large text. Motion must serve orientation or meaning; respect reduced-motion preferences.
6. Inspect rendered output at narrow and wide widths and at zoom. Compare the actual images with the approved direction, not only the source code. Keep one consolidated correction list ordered by impact.
7. Separate brand judgement from defects. Pure black, Inter, cards, gradients, brutalism or restraint are not universally wrong. Justify choices against this brief. Do not inherit another repository's personal aesthetic as ACO law.
8. Deliver a coherent system plus actual artefacts: tokens, components, page/state inventory, implementation notes, screenshot references and explicit unresolved decisions.

## Acceptance
The main action and content hierarchy remain legible without explanation; approved typography and imagery survive realistic content; responsive behaviour and focus have execution evidence. If rendering tools are absent, return a design specification and an untested implementation, not a visually verified website.

## Handoff
The user owns the route. Art/design direction owns expression; product/engineering owns implementation feasibility. Technical convenience must not silently redesign the work. Use a scoped design contract and a small evidence packet, not a new global company context.
