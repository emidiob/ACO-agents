# Change an existing design without losing its function

Observe the actual page and task before editing. Capture a baseline at a useful narrow and wide viewport when tools allow; inspect routes, controls, content and states. Separate visual weaknesses (hierarchy, type, rhythm, identity) from functional defects (navigation, focus, error recovery, overflow). Prioritize blockers, comprehension and then polish.

Choose the smallest effective intervention. To strengthen a timid page, increase the contrast between primary and secondary information or make imagery more specific. To simplify a noisy page, remove repeated structure and competing emphasis while keeping necessary controls discoverable. To refine a nearly finished page, align type, spacing, state feedback and asset treatment. Don't indiscriminately remove borders, cards, color or animation.

Preserve routes, field names, event behavior, data contracts and accessibility hooks unless the request requires changing them. Don't replace an established product with the bundled demo. Reuse original assets and copy unless their replacement is in scope.

Compare before/after with the same content, viewport and task. Explain which observed problem each change solves. Recheck interactions after visual edits. If a proposal has not been implemented or browser-reviewed, label it as such. User taste feedback is evidence; generic trend scores are not acceptance criteria.
