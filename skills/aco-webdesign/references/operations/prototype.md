# Compare functional alternatives

Build multiple distinct interactions behind the same data contract and a simple switcher. Keep enough real state to test the task. Compare task completion, clarity and layout before integrating the selected variant.

Use the [prototype comparison exporter](../project-tools.md) to mount the working alternatives, preserve their state while switching, inspect three widths and record observations. The exporter does not generate distinct interaction designs from a brief; build those before comparing.

Completion evidence: Each alternative works; selection is based on observed behavior and the brief.

Use the project’s existing conventions and available tools. Report missing capabilities explicitly; a written procedure is not runtime proof.
