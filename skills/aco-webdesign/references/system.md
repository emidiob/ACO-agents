# Build a usable design system

Start with existing tokens/components and identify genuine inconsistencies. Extend the smallest coherent system. For new work define semantic roles for page/surface/text/muted/accent/border/focus, a type hierarchy, spacing rhythm, content widths and responsive behavior. Record them in existing project conventions; don't create a pile of planning files for a one-page edit.

Choose typefaces for the subject, language coverage, available license and loading cost. System fonts can be intentional; a particular popular font is not automatically wrong. Test long headings, real paragraph lengths, labels and numeric data. Validate text/background contrast in the rendered combinations, including hover, disabled and error states; a palette file cannot certify the whole interface.

Derive components from repeated behavior and content. Preserve native semantics for buttons, links, labels, lists and tables. Design default, hover, focus, active, disabled, loading, empty, error and success states where they actually occur. A gradient or a rounded card is a choice to justify, not a forbidden token. Prefer meaningfully different hierarchy to decoration everywhere.

Name component variants by role. Keep spacing and type responsive without hiding overflow bugs. Distinguish a demo token set from an approved brand system. The bundled recipes and examples are original ACO starting points, not a replacement for reference inspection or component accessibility testing.
