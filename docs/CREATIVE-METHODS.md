# Creative methods: native and portable

| Method | Native responsibility | Concrete local helper | Actual generation dependency |
|---|---|---|---|
| Capture | Four photographic layers, seven camera approaches, consistent series | Reference inventory with hashes | Available image tool when generation is requested |
| Image | New image, bounded edit, series and anchor preparation; inspect outputs | Reference inventory with hashes | Available image generation/editing tool |
| Video | Mode selection, action/camera, storyboard, continuity, provider translation, playback review | Reference inventory with hashes | Available video tool and verified interface settings |
| Genjutsu | Source inspection, real anchors, recreation/transfer/repair | ffmpeg extraction and reference-packet checks | Image tool for changed anchors; separately authorized video generation |
| Motion | Designed graphics and interactive animation | Scaffold, render metadata checker, runnable examples | Project engines such as Remotion and browser animation |

These five creative methods share canonical ACO sources. `scripts/generate.py` distributes shared reference documents and installers; edit the source, not the generated copies. Capture's source remains the Concierge playbook, visual/shot methods remain in Genjutsu, the project contract and installer remain in Motion, and the reference inventory source is `scripts/creative_reference_inventory.py`.

Export any listed skill with `python3 scripts/package_creative_skill.py --skill aco-image --output /outside/library/aco-image.zip`. The archive includes the original license, a hash manifest and all required local Markdown references. The installer previews by default, supports Claude/Codex global or project roots and refuses locally modified/unmanaged installations. Existing full ACO installs should use the integrated installer. VS Code support means the corresponding agent extension, not a separate VS Code runtime.

Verification covers independent extraction, per-file hashes, installation into isolated Claude/Codex layouts, missing/duplicate reference rejection and preservation of existing output. It does not certify fresh host discovery, external providers, visual results or commercial quality. No paid model generation was performed for this packaging change. Existing Genjutsu and Motion tests remain applicable; candidate technical adapters remain candidates.

The other native entries are offices, context tools, Concierge and help/registry discovery. They retain their integrated role and protocol dependencies; this change does not falsely advertise those organizational workflows as standalone creative generators.
