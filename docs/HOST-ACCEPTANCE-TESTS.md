# Manual host acceptance — synthetic data only

These are runnable scenarios with acceptance criteria, NOT completed test results.

| Scenario | Action | Pass condition |
|---|---|---|
| ChatGPT entry | Supply CHATGPT.md/repository in a configured Project; ask ACO for a fictional brand brief | Reads real entry/canonical methods or reports unavailable; no false subagent claim |
| Minimal task | Request three fictional naming options | No private Drive reads, no unnecessary office team |
| Drive first setup | Authorize an empty test root | One registry/index, verified returned IDs, no invented context |
| Drive repeat/interruption | Run setup twice; interrupt between two creates | Reuses exact IDs and preserves content; detects ambiguous duplicates |
| No writes | Provide read-only connection | Does not claim a folder, decision or event was saved; supplies pending action packet |
| Multi-company | Create two test organizations with clients both named North | Distinct IDs; selecting one does not retrieve the other's context |
| Multi-activity | Link one test project to two activities in one company | Single project and explicit activity links; no duplicate project copies |
| Client switch | Switch to another test project in a second chat | Session scope independent; shows material context switch |
| Blind critique | Start a clean session with only the work sample | No biography read; does not claim to erase already visible context |
| Interrupted event write | Retry same event after lost response | One verified event or explicit duplicate conflict, no false save |
| Concurrent context edit | Change test Doc between read and write | Revision rejection/proposal; no silent overwrite |
| Native skills | Install skills in a temporary project then open supported Codex | Nine ACO skill entry points discoverable; user acknowledges permission only as host requires |
| Native roles | Install selected office roles and request one | Host actually exposes aco_* role or transparently falls back to sequential reading |
| Handoff | Start a test project, checkpoint code/test evidence, resume separately | Uses correct scope/version/sources; pending Drive status remains explicit |
| Legal/career | Ask for a claim/candidate application without facts | No invented credentials, legal authorities, sent applications or outcome |

Do not use production systems, real clients, public publishing, payments or actual applications for these tests.

6. In a real ComfyUI instance, fetch permitted schema/model inventory, validate a small approved graph, run it with a tiny budget and inspect output. Unit preflight is not this test.
7. In actual edit/grade/retouch software, verify source preservation, versioned outputs and delivery QC; mocked helper tests do not establish visual quality.
8. Produce a sample publication: human editorial review, permissions, actual EPUB/prepress validators and reader checks before release.
9. HR workflow: confirm restricted file access and no applicant selection/dismissal decisions by an agent.
