# Known limitations — 0.7.3

- ACO is a role/method library plus local utilities, not an always-on service, fine-tuned model, professional staff or access-control product.
- The 363 specialist roles are preserved. Automated checks verify structure, routing contracts and selected behavior cases; they do not establish professional quality across every role or domain.
- Local unit/integration tests do not demonstrate better artworks, writing, brand strategy, sales, legal outcomes, hiring outcomes or financial performance. Human review remains necessary where judgment matters.
- Source review covers selected publisher pages, catalogues and repository overviews, not exhaustive security, copyright or dependency audits. Recheck current terms and security before operational use.
- The 99 optional resources are references/tools, not mandatory dependencies. Listing a resource does not mean it is installed, connected, authenticated, authorized, secure, free or appropriate.
- Protected/reference-only material remains consultation-only. ACO does not grant rights to reproduce upstream standards, prompts, code, datasets, fonts, models or brand assets.
- A PATH result is not a successful command run; a connected-app name is not proof of a working write action; a supplied evidence string is not authenticated provider evidence.
- `integration-resolve` consumes the current adapter/capability inventory supplied to it. It does not discover hidden accounts, authenticate a provider or perform the external action itself.
- The two optional code-memory resources are not installed, bundled or execution-tested by ACO. Hybrid Memory can operate without either; Git/source control remains authoritative for code.
- The privacy/PII release scan is a conservative heuristic gate, not proof that a repository contains no sensitive information. It must be combined with human diff review and normal secret scanning before publishing.
- No authenticated Drive/social/email/WhatsApp/phone action, real scheduler setup, paid rendering, ComfyUI GPU processing or desktop-DCC operation is established by the package test suite.
- Drive/canonical persistence is optional at task start. If an already-authorized store is unavailable, ACO continues with available context; a requested or materially useful durable update may remain pending.
- Hybrid Memory is a routing policy, not a new database product. Durable semantic context may live in a canonical store; code structure remains rebuildable/local; research corpora remain in their source systems; temporary task state should remain temporary.
- Context separation is a behavioral design, not encryption or account isolation. v0.7.3 rejects wildcard/global cross-scope permission and requires exact private scope IDs in the local resolver, but real file/app permissions, separate sessions and minimum disclosure remain necessary. A blind prompt cannot erase context already shown to a model.
- Delegation defaults to resolving reasonable reversible professional choices, but ACO must still ask for genuinely decisive missing facts, irreducible personal preference, private-scope ambiguity or consequential authorization.
- `handoff-check` validates handoff structure/evidence presence, not whether the evidence itself is true.
- The deterministic router is advisory and benchmark-limited. Its packaged 98.57/100 holdout score does not imply universal routing accuracy; unusual, multilingual or underspecified requests may still require Concierge clarification.
- `routing-examples.json` is generic package data used by the local deterministic router, not user memory and not model fine-tuning.
- The packaged behavioral simulation is same-model structured review. Its score is useful regression evidence, not an independent benchmark or proof of artistic, curatorial, design or strategic quality.
- `delegation-benchmark` and `integration-benchmark` are deterministic conformance checks over packaged cases. They do not prove performance on every future request or host.
- `context-budget` uses static character/package estimates. It is not provider token telemetry, latency measurement or proof of the active context window.
- Local cleanup uses snapshots and reviewed plans. Live Drive mutation requires actual authorized actions, an inspected scope and read-back verification. A local mirror is not synchronization.
- Future changes to generated files require regenerate → manifest → validation → tests. User modifications or nonstandard old releases can make migration stop safely; do not bypass collisions with deletion.
- Shell helpers target macOS/Linux with Python 3.11+. A real host/version must verify native skill/agent discovery. Windows users need an appropriately configured environment; native Windows installation is not certified.
